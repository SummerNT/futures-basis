# 股指期货贴水监控

监控中证 500 / 中证 1000 / 沪深 300 / 上证 50 四个股指期货品种的年化贴水，
给出换月窗口信号，并测算持仓安全垫。

纯 Python 标准库实现，**不需要安装任何第三方包**。

> **在线看板**：<https://summernt.github.io/futures-basis/>
> **实操手册**：<https://summernt.github.io/futures-basis/manual.html>
>
> 每个工作日北京时间 16:00 由 GitHub Actions 自动更新。

---

## 一、5 分钟上手：每天只看三个数

如果你没时间看完整页，只看这三处，够用了：

| 看哪里 | 看什么 | 怎么判断 |
|---|---|---|
| ① 主力合约年化贴水 | 一个百分数，比如 `6.93%` | 现在滚进去，一年大概能收这么多贴水 |
| ② 它的**分位** | 比如 `21.3%` | 低于 30% = 贴水偏薄，不划算；高于 70% = 贴水丰厚 |
| ③ 换月窗口的分位 | 比如 `17.2%` | 低于 75% = 别急着换月；高于 75% = 可以换了 |

**一句话记法：分位管买卖，价差管换月，斜率管换到哪个月。**

- 加仓减仓，看 ① 和 ②
- 换不换月，看 ③

## 二、看板逐块说明

从上往下，每块是干什么的、怎么看、什么时候用。

### 1. 顶部结论条

自动生成的一句话总结，比如：

> **IC 中证500** 主力 IC2612 年化贴水 **6.93%**，处于近一年 **21.3%** 分位 —— 贴水偏薄 · 性价比低。
> 　近月−次月价差 **40** 点（17.2% 分位），尚未到换月窗口。

"懒人模式"用，一句话交代今天的全部结论。

### 2. 卡片「主力合约年化贴水」

- **大数字**：当前主力合约的年化贴水率
- **现货 / 主力 / 中位数 / 样本**：计算依据
- **彩色标签**：自动判断当前贴水处于什么状态

| 标签 | 分位区间 | 含义 |
|---|---|---|
| 贴水丰厚 · 历史高位 | ≥ 70% | 滚进去性价比好，可以考虑加仓 |
| 贴水中性偏高 | 45~70% | 正常水平 |
| 贴水中性偏低 | 25~45% | 一般，不必着急 |
| 贴水偏薄 · 性价比低 | < 25% | 安全垫薄，不建议重仓进场 |
| 期货升水，不利多头 | 年化 < 0 | 贴水消失，吃贴水的逻辑没了 |

**分位是什么**：把过去 244 个交易日的年化贴水从小到大排队，当前值排在第几百分位。
21.3% 分位 = 过去一年里有 79% 的日子贴水比现在厚。

### 3. 卡片「换月窗口」

- **大数字**：近月减次月价差的历史分位
- **价差**：比如 `40 点`，意为近月合约比次月合约贵 40 点
- **折合月差**：价差 ÷ 跨月数，用来比较换到不同月份的性价比

**为什么重要**：换月 = 卖掉贴水快吃完的近月，买进贴水还满的远月。
近月越贵（相对远月），这一卖一买越划算。价差分位 > 75% 就是窗口。

**什么时候用**：临近换月的那两周，每天扫一眼。到 75% 就准备动手。

### 4. 图「主力合约年化贴水历史」

- **蓝线**：每天主力合约的年化贴水
- **橙色虚线**：过去 244 天的中位数
- **红点**：当前值

**怎么看**：蓝线在橙线上方 = 比历史中位数厚，下方 = 薄。

**注意**：主力换月时曲线会跳一下，这是换了个合约，不是数据错误。

### 5. 图「各期合约贴水对比」

这张图最容易被忽略，但信息量很大。

- **每个柱子 = 一个交割月份的合约**（`25/10` 表示 2025 年 10 月合约）
- **取样规则**：取该合约"剩余约 30 天"那一天的读数

**为什么要统一到剩余 30 天**：不同到期日的合约不能直接比 —— 剩 200 天的合约
贴水天然比剩 30 天的深。统一时点才比得公平。

**怎么看**：
- 柱子高出橙色中位线 = 那期合约贴水厚
- **柱子跑到 0 以下 = 那期是升水**，滚多头不但吃不到还倒贴（2026 年 2 月合约就是 −4.83%）
- 红色柱 = 它同时也是当前主力

**什么时候用**：判断"现在的贴水在历史上算什么水平"，比看单日曲线更稳。

> 注意：这张图比的是**各期合约的贴水水平**，不是斜率。斜率看下一张「期限结构斜率」。

### 6. 图「期限结构 · 各合约贴水」← 这张最容易看不懂

**它在说一件事：同一天，不同到期月份的合约，贴水分别是多少。**

- **横轴**：合约，从左到右由近到远（IC2611 → IC2612 → IC2703 → IC2706）
- **红柱**：贴水**点数**（现货 − 期货），1 点 = 200 元
- **蓝线**：**年化**贴水（把剩余时间考虑进去后的百分比）

两种读法要分清：

| 看到什么 | 说明什么 |
|---|---|
| 红柱从左到右变高 | 远月贴水点数更深 —— 正常现象，时间越长累积越多 |
| **蓝线往右走低** | 远月年化更低 → 换到远月不划算，换到次月就行 |
| **蓝线基本走平** | 换到哪个月年化差不多 → 看流动性和手续费，选能少换几次的 |

**以 IC 现在的数据为例**：IC2611 年化 6.21%、IC2612 6.93%、IC2703 8.18%、IC2706 8.51%
—— 蓝线往右走高，说明远月年化更划算，但远月持仓量小、买卖价差宽，急平仓时滑点大。

**为什么要分"点数"和"年化"两个维度**：
- 点数告诉你"这一手到期能收多少钱"
- 年化告诉你"这笔钱摊到时间上划不划算"
- 只看点数会误判：远月点数大，但要多占用几个月资金

### 7. 图「期限结构斜率 · 下季 vs 当季」

- **一条线**：每个交易日的斜率年化值
- **大圆点**：每月最后一个交易日的读数（带数值标签，方便按月对比）

**公式**：斜率 =（下季价 − 当季价）÷ 当季价 × 365 ÷ 两个到期日之间的天数

"下季"和"当季"都指季月合约（3/6/9/12 月）。比如现在是 IC2612 与 IC2703 的比较。

**怎么读**：

| 看到什么 | 说明什么 |
|---|---|
| 数值为负（多数时候） | 远月比近月便宜，正常现象 |
| **负得越多** | 曲线越陡，往远月换的补偿越厚 |
| 接近 0 | 期限结构平坦，换远月几乎没有额外收益 |
| 由负转正 | 远月反而更贵（升水结构），这时往远月换要吃亏 |

**和「期限结构」那张图的区别**（很容易混）：

- 「期限结构」= **某一天**的横截面，四个合约一起看 → 回答"今天换到哪个月"
- 「期限结构斜率」= **同一口径随时间的纵向变化** → 回答"现在往远月换值不值，比过去如何"

**什么时候用**：决定"要不要从次月换到季月"时看这张。线越往下走，说明远月的补偿在变厚。

> 参考值：2026-10-23 IC 斜率 −9.04%，意味着从当季换到下季，年化能多拿约 9 个百分点的贴水补偿。

### 8. 图「近月 − 次月价差历史」

- **蓝线**：每天"最近月合约 − 次近月合约"的价差
- **红色虚线**：当前值

**怎么看**：这条线越往上，说明近月相对远月越贵，换月越划算。配合第 3 块卡片的分位一起看。

**一个反直觉的地方**：不是"越临近到期越好"。
有时候远月贴水自己收敛得更快，反而把价差压下来。所以要看分位，不要凭"快到期了"的感觉。

### 9. 表「四品种横向对比」

并排看六个数字：现货、主力年化、近一年中位、年化分位、近−次月价差、价差分位。

**什么时候用**：
- 想知道 IM（中证1000）是不是比 IC 更划算
- IC 贴水薄的时候，看看别的品种有没有机会

**注意**：IM 的贴水通常比 IC 厚，但波动也更猛；IF / IH 通常更薄。

### 10. 卡片「持仓安全垫」

输入四个数，实时算出风险状况：

| 输入 | 说明 |
|---|---|
| 本金（万元） | 投在这条策略上的钱，不是账户总资产 |
| 手数 | 持了几手 |
| 开仓价 | 开仓时的点位（**换月后必须改**） |
| 保证金比例 | 期货公司实际收的，一般 13~15% |

输出四个数：

| 输出 | 含义 |
|---|---|
| 保证金占用 | 实际被冻结的钱 |
| 占用率 | 保证金 ÷ 本金。**超过 40% 就该警惕** |
| 当前杠杆 | 名义价值 ÷ 本金。1 手 IC 约 2.7 倍 |
| **距追保** | 指数还能跌多少，就会被要求追加保证金 |

**距追保的读法**：显示"1623 点"或"24.1%"，意思是中证500 从这里再跌 24.1%，
可用资金归零，期货公司要求补钱，否则强平。

**这是整页最该盯的数字。**

### 11. 表「合约明细」

每个在交易合约的：收盘价、剩余天数、贴水点数、年化、名义价值、1 手保证金、持仓量。

**什么时候用**：
- 准备开仓，算要准备多少钱
- 准备换月，对比新旧合约的保证金和流动性
- 看持仓量判断流动性（低于 5 万手的合约，买卖价差会变宽）

## 三、本地运行

需要 Python 3.9 或更高版本。

```bash
cd futures-basis
python run.py
```

跑完生成：

| 文件 | 说明 |
|---|---|
| `docs/preview.html` | 本地预览页，双击用浏览器打开 |
| `data/metrics.json` | 计算后的全部指标 |
| `data/history.json` | 期货日行情历史缓存 |
| `data/spot.json` | 现货指数历史缓存 |

首次运行会回填约 420 天历史（约 290 个交易日、两分钟），之后每次只补缺失的那几天。

**本地跑只写 `docs/preview.html`，不碰 `docs/index.html`。**

`docs/index.html` 归 GitHub Actions 独占：它是 Pages 发布的内容，由 CI 生成并提交。
本地另开一个文件，两边的写入物理隔离，所以本地跑多少次都不会和远端打架。

想强制本地覆盖 index.html（一般不需要）：

```bash
python run.py --publish
```


### 关于"每次都重新生成 HTML"

**是的，默认每次都重写 `docs/index.html`，而且必须如此。**

原因：这个页面是**单文件设计**，所有数据在生成时直接写进 HTML 里。
好处是双击就能打开、能离线看、托管到任何静态服务都不用配置。
代价是数据一变，HTML 就得重写一遍。

生成只是字符串拼接，几毫秒，不是瓶颈 —— 真正耗时的是抓网络数据。

如果你只想要数据不想动页面：

```bash
python run.py --no-render
```

> 另一种做法是让 HTML 去读外部 JSON，这样 HTML 固定不变。
> 但浏览器用 `file://` 打开本地文件时，读同目录 JSON 会被安全策略拦截，
> 必须额外起一个本地服务器 —— 为了省几毫秒引入一个服务器，不划算。

### 常用参数

```bash
python run.py --days 30      # 只回填最近 30 天，适合日常增量
python run.py --backfill     # 忽略本地缓存，全部重抓
python run.py --no-render    # 只更新数据，不生成页面
```

> **注意**：交易日 15:30 之后数据才完整。盘中运行会拿到不完整的当日文件，
> 脚本发现当天数据缺失时会自动沿用前一个交易日。

### 本地改动怎么提交（重要）

`data/` 和 `docs/` 这两个目录由 **GitHub Actions 独占维护**。本地改完代码后：

```bash
git add src/ .github/ run.py
git commit -m "你的说明"
git push
```

**不要用 `git add -A` 或 `git add .`** —— 它们会把本地跑 `run.py` 生成的
`data/*.json` 和 `docs/index.html` 一起带进去，而 Actions 也在提交同样的文件，
push 时必然冲突。

如果只是想本地预览效果，跑完 `python run.py` 直接双击 `docs/index.html` 看就行，
不需要提交任何东西。

万一已经冲突了（`both modified: data/metrics.json`）：

```bash
git checkout origin/main -- data/ docs/index.html
git add data/ docs/index.html
```

## 四、部署到 GitHub Pages（手机随时看）

做完之后，每个交易日 16:00 自动更新，你只需要收藏一个网址。

### 1. 建仓库

1. 注册并登录 GitHub
2. 右上角 `+` → **New repository**
3. 名字填 `futures-basis`，选 **Public**（Pages 免费版需要公开仓库）
4. 不勾选任何初始化文件，直接 **Create repository**

### 2. 上传代码

在 `futures-basis` 目录下执行（`你的用户名` 换成实际用户名）：

```bash
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/你的用户名/futures-basis.git
git push -u origin main
```

### 3. 打开 Pages

仓库 → **Settings** → 左侧 **Pages**：

- Source 选 **Deploy from a branch**
- Branch 选 **main**，目录选 **/docs**
- 点 **Save**

等 1~2 分钟，顶部出现网址：`https://你的用户名.github.io/futures-basis/`
加到手机浏览器书签，或"添加到主屏幕"。

### 4. 确认自动任务已启用

仓库 → **Actions** → 若有提示横幅，点 **I understand my workflows, go ahead and enable them**。

`daily-refresh` 会在每个工作日 UTC 08:00（北京时间 16:00）自动运行。
想立刻看效果：进 `daily-refresh` → 右侧 **Run workflow**。

## 六、配置你的持仓

新建 `data/position.json`（只影响推送里的"安全垫"那一行，页面上的计算器独立工作）：

```json
{
  "product": "IC",
  "code": "IC2612",
  "capital": 500000,
  "lots": 1,
  "open_price": 6742.0,
  "margin_rate": 0.13
}
```

| 字段 | 含义 |
|---|---|

| `lots` | 手数 |
| `open_price` | 开仓成交点位 |
| `margin_rate` | 期货公司实际保证金比例，一般 0.13~0.15 |

## 七、数据口径

| 指标 | 算法 |
|---|---|
| 贴水点数 | 现货 − 期货（正数 = 期货贴水，对多头有利） |
| 年化贴水 | (现货 − 期货) / 现货 × 365 / 剩余自然日 |
| 剩余天数 | 合约月第三个周五 − 当日（未处理节假日顺延） |
| 主力合约 | 当日持仓量最大的合约 |
| 分位 | 近 244 个交易日内当前值所处的位置 |
| 换月价差 | 最近月 − 次近月收盘价（正数 = 近月偏贵） |
| 合约对比取样 | 各合约剩余天数最接近 30 天的那一天（±10 天内） |

**重要**：本程序算的是**表观贴水**，未扣成分股分红。
券商研报常用扣除分红后的净贴水口径，两者通常差 1~2 个百分点。

交叉验证：2026-10-21 本程序算 IC 主力年化 **9.71%**，国信证券研报同日为 9.19% / 9.78%
（日报 / 周报口径），差异落在分红处理上，说明算法正确。

数据来源：

- 期货日行情：中国金融期货交易所每日统计 <http://www.cffex.com.cn>
- 现货指数：新浪财经

## 九、常见问题

**Q：页面上的图不显示？**
页面从 CDN 加载 ECharts，需要联网。断网时文字和数字仍然可用。

**Q：某天没有更新？**
节假日不更新属于正常。工作日也没更新，去仓库 Actions 看那次运行是否报错。

**Q：主力合约曲线中途跳了一下？**
主力换月了（持仓量转移），曲线换了个合约，属正常。

**Q：「各期合约对比」里怎么没有当前主力？**
那张图只收录"已走到剩余 30 天附近"的合约。当前主力还剩 50 多天，还没到取样点。
想看在交易的合约，看「期限结构」和「合约明细」。

**Q：想改回填的历史长度？**
改 `src/config.py` 的 `BACKFILL_DAYS`，或运行时用 `--days`。

**Q：想调整换月信号的阈值？**
改 `src/config.py` 的 `ROLL_SIGNAL_PCT`（默认 75）。
